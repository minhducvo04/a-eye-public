# A-eye data export v1

Offline handoff for a teammate's SpacetimeDB database. `scripts/export_data.py` writes seven NDJSON
files and `manifest.json`; it does not connect to a service. `schemas/export-v1.json` is the standalone
Draft 2020-12 export schema, separate from the live WebSocket contract. Each row carries `v: 1`,
`entity`, and a stable pseudonymous `id`. Every field has `description`, `unit`, and `privacy` annotations.
Unknown measurements are `null`, never invented zeroes. Changes to field meaning require a new schema version.

## Run

Use the project's Python environment with the existing `jsonschema` dependency. No new dependencies.
Output must be a new directory. These commands create local files only:

```sh
python scripts/export_data.py --sample --output /tmp/aeye-sample
python scripts/export_data.py --source /path/to/local-snapshot --call-id SOURCE_CALL_ID --output /tmp/aeye-one
python scripts/export_data.py --source /path/to/local-snapshot --since 2026-10-24 --until 2026-10-25 --output /tmp/aeye-day
python scripts/export_data.py --source /path/to/local-snapshot --memory-dir /path/to/local-memory --call-id SOURCE_CALL_ID --output /tmp/aeye-memory
```

Real exports require `A_EYE_EXPORT_HASH_KEY` set to a secret of at least 32 bytes in the environment.
Generate a random secret using your local secret manager. Keep the same key for stable joins across exports;
rotating it changes every pseudonym. Do not give the key to the teammate or put it in shell history, a snapshot,
a manifest, or git. The script never loads `.env`. Sample mode uses a fixed synthetic-only key and never reads
application storage. Sample mode cannot be mixed with a source or selectors.

Dates mean UTC midnight. Date ranges select **calls started** in `[since, until)` and include all their child
records, even if a child happened after the end boundary. A call with unknown start time can be selected by
ID but cannot be selected by date. ISO datetimes must include a timezone. Missing matches produce empty tables
and zero manifest counts. Private calls and their children are always excluded; unknown privacy is an error.

## Current storage boundary and input contract

This checkout does **not** persist a complete call/turn/step/tool/safety/proof archive. `server/logs.py` emits
allowlisted stdout metadata, `server/ws2.py` emits timing events, and the proof API reads runtime counters.
The exporter cannot recover missing history from those sources. It does not scrape logs or browser state,
start recording transcripts, or change another package's capture behavior.

Its explicit local snapshot input is a directory with `call.ndjson` and optional `<entity>.ndjson` files
using the table names below. A missing child file means no available records, not evidence that no events
occurred. A producer must save these metadata snapshots to use the non-memory tables; that capture wiring is
not included in this package. Each input row uses the output field names, except:

- `id` and `call_id` are stable **source** strings, not pre-hashed output values. Child IDs must be unique per
  entity within a call; call IDs must be unique across the snapshot. Use the same source IDs on every export.
- Call `user_id` is the raw local identifier (or null). IDs are HMAC-SHA256 hashed with separate domains for
  users, calls, and child entities. Child IDs also include their parent call identity.
- `v` and `entity` are generated by the exporter. Missing nullable output fields become null. Missing mandatory
  values fail validation. A call must explicitly have boolean `private`; no inferred public default.
- A turn's `text` is exported only with the input-only boolean `text_reviewed: true`. This asserts that the
  producer/operator reviewed the text and removed third-party speech. Otherwise text is null for **every**
  role, including assistant text that might quote another person. This is provenance, not automatic PII detection.
- Unknown keys are dropped. All rows are validated before any directory is published; malformed rows,
  duplicate IDs, orphan rows in the selected dataset, invalid durations, and invalid timestamps fail the export.

Minimal source call row:

```json
{"id":"local-call-123","started":"2026-10-24T12:00:00Z","ended":null,"mode":"pc","private":false,"user_id":"local-owner"}
```

`--memory-dir` adapts the actual plaintext `<person>/log.jsonl` layout from `server/memory.py`:
`call` joins to the call catalog's full ID or its first 12 characters; ambiguous prefix matches fail.
Each tagged object becomes a `memory_event`: `tags[].tag` → `item`, `tags[].near.label` → `place`,
`kind` → `sighting`, and `t` remains Unix seconds. Its stable source identity includes the person folder,
record ID, and tag index. Unmatched calls and untagged scene notes produce no memory rows. Do not supply both
an already-adapted memory snapshot and the same native records. The call catalog is required because native
memory lacks trustworthy call start/end/private metadata. Private-call exclusion still applies.

Encrypted Fernet memory logs are deliberately **not** silently skipped or decrypted; they fail parsing.
An authorized local producer must supply an equivalent plaintext metadata snapshot without media or scene notes.
The adapter opens only `log.jsonl`, never `owner.json`, images, crops, videos, or embedding files; symlink inputs
are refused. Never point coding agents at real personal memory. Development and tests use synthetic records.

## Tables

All tables use `id` (64-character string) as the primary key. Child `call_id` matches `call.id`.
`v` and `entity` are common columns; indexes below are suggestions for the teammate's query patterns.

| Table/file stem | Row meaning | Suggested secondary indexes |
|---|---|---|
| `call` | One call: UTC start/end, mode, private flag, user pseudonym | `started`, `user_id`, `mode` |
| `turn` | One speaker turn, reviewed text, route, brain label, elapsed timing and latency milliseconds | `call_id`, `(call_id, t_ms)` |
| `step_progress` | A recorded step progress observation: task, step, hints used, producer-defined level | `call_id`, `(call_id, task, step)` |
| `memory_event` | A tagged object sighting and nearby place, with Unix-second timestamp | `call_id`, `(call_id, t)`, `item` |
| `tool_call` | Tool name, success boolean, duration; no arguments or result payload | `call_id`, `name` |
| `safety_stop` | A code rule stopping an action, with Unix-second timestamp | `call_id`, `rule_id`, `t` |
| `proof_counter` | A counter snapshot; saved pictures are device-wide, other counters are per call | `call_id`, `(call_id, t)` |

Proof values are cumulative snapshots, not deltas: do not sum successive snapshots. Cloud request counts include
failed attempts and may include public non-AI requests. Byte counts exclude headers, TLS, and transport overhead.
Null counters mean unavailable; these exports do not independently establish physical-device or privacy proof.

## Loading into SpacetimeDB

The teammate owns the database module and credentials. No upload, database publish, or cloud verification was
performed here. The handoff is NDJSON, not an automatic SpacetimeDB import format.

1. Check manifest `v` and compare `schema_sha256` against SHA-256 of the exact schema file bytes. Validate each
   row against that schema and compare line counts for every file with `counts`. The hash identifies the schema;
   it is not a signature or a checksum of the dataset.
2. Define one table per entity in the teammate's module. Use string primary keys and the indexes above. Keep
   personal tables private and enforce authorized reads/imports. A field annotated `public` describes metadata
   sensitivity; it does not grant permission to make the table public.
3. Map strings to strings, booleans to booleans, nonnegative counters to suitable unsigned integers, and fractional
   millisecond/Unix-second values to floating point. Preserve nullable values as the SDK's optional type. Keep
   RFC3339 UTC timestamps as strings, or explicitly convert to the module's timestamp type at ingestion.
4. Add an authorized import reducer per entity (or one dispatch reducer) that accepts a JSON string. Parse it,
   enforce the v1 allowlist/types, check the caller, reject private calls, enforce child-parent references, and
   upsert by stable `id`. For repeat IDs, require matching immutable identity and apply the team's update policy.
   Validate again on the server; a client-side check is not an authorization boundary.
5. Import `call.ndjson` first, then the six child files. Send each line as **one string argument** through the
   generated SDK reducer binding; SDK serialization handles escaping. Use batches/transactions as appropriate
   for the team's module. Check reducer success before checkpointing a row so retrying the import is safe.
6. Query each table for imported IDs and compare counts with the manifest. Whole-table counts can include older
   imports, so verify this batch's IDs. Retain the manifest with the teammate's ingestion receipt.

Reducer calls are the documented write mechanism ([SpacetimeDB reducers](https://spacetimedb.com/docs/functions/reducers/)).
For an operator smoke check, the CLI supports `spacetime call <database> <function> [arguments...]`; consult
`spacetime call --help` for the installed version's quoting and connection options
([CLI reference](https://spacetimedb.com/docs/cli-reference/)). A reducer named `import_call` must first be
implemented by the teammate; this repository does not create it. Do not paste private rows into shell history.

## What never leaves the device through this exporter

Frames, audio, crops, raw third-party transcripts, scene captions/notes, embeddings, tool arguments/results,
owner credentials, unknown fields, the HMAC secret, and private-call records are excluded. The schema explicitly
marks `frames`, `audio`, `crops`, and `raw_transcripts` as `never-export` and rejects their presence. An allowlist
also drops aliases such as `frame_b64`, arbitrary nested payloads, and all unrecognized fields. Structured content
cannot be hidden in scalar fields without failing type validation.

Exported item/place labels and reviewed text are still personal data; HMAC IDs are pseudonyms, not anonymization.
The exporter cannot detect sensitive prose deliberately placed inside an allowed string. Review personal fields
before handing files to the teammate. Output directories are private temporary directories (0700), files are 0600,
and no network code is used. Application Rewind behavior is outside this offline export boundary.
